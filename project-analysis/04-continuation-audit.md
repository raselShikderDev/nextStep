## Verified Findings
Important findings confirmed directly from the current source code include:
- **Modular, feature‑based architecture**: Each feature (auth, payment, user, document, service, request) resides in its own folder under `src/module/` with dedicated controller, service, route, and Prisma model files.
- **JWT‑based authentication**: Access and refresh tokens generated via `jsonwebtoken`, secrets loaded from environment variables, password hashing using `bcryptjs` with configurable rounds.
- **Validation middleware**: Zod schemas used in validation modules (e.g., `src/module/auth/auth.validation.ts`) and parsed in controllers (e.g., `auth.controller.ts` uses `loginValidationSchema.parse(req.body)`).
- **Error‑handling middleware**: Global error handler (`src/middleware/globalErrorHandler.ts`) catches Zod, Prisma, JWT, and custom AppError instances, returning structured JSON responses.
- **Rate limiting**: Redis‑backed global rate limiter (`src/middleware/globalRateLimiter.ts`) using `rate-limiter-flexible` with 100 points per 60 seconds, blocking for 60 seconds on exceedance.
- **Prisma ORM**: Type‑safe client generated from Prisma schema spread across multiple `.prisma` files (`user.prisma`, `service.prisma`, etc.), with relations defined and used throughout services.
- **File upload endpoint (`POST /upload/:requestId`) lacks authentication**: Route defined in `src/module/document/document.route.ts` uses only `upload.any()` middleware, no `authCheck`.
- **Upload controller does not persist `requestId`**: `src/module/document/document.controller.ts` passes `req.files`, `req?.user?.id`, `req?.user?.role`, `req.body.description` to the service but omits `req.params.requestId`; service (`src/module/document/document.service.ts`) creates `RequestDocument` records without `requestId` field.
- **Request IDOR vulnerability**: `GET /requests/:id` route in `src/module/requests/requests.route.ts` protected only by `authCheck(Role.ADMIN, Role.SUPER_ADMIN, Role.MANAGER)`; service layer (`src/module/requests/requests.service.ts`, `getSingleRequest`) performs `prisma.serviceRequest.findUnique({ where: { id } })` without ownership or assignment check.
- **Public static file serving**: `src/app.ts` mounts `express.static('/uploads')`, making uploaded files directly accessible via `/uploads/<filename>`.
- **Refresh token rotation not implemented**: `auth.service.ts` `refreshToken` function generates a new access token but does not invalidate the old refresh token (no versioning or revocation list).
- **Ad‑hoc logging**: Instances of `console.log`/`console.error` found in code (e.g., `auth.controller.ts` line 95, `auth.service.ts` in OTP handling), no structured logger (e.g., pino/winston) observed.
- **No test suite**: Absence of `__tests__`, `test/` directories, or test scripts in `package.json`.
- **Role enum lacks `GUEST`**: Prisma enum `Role` (in `prisma/enums.prisma`) contains `USER`, `MANAGER`, `ADMIN`, `SUPER_ADMIN`; no `GUEST` value.
- **ServiceRequest model uses `userId` nullable**: Links request to authenticated user optionally; guest requests rely on `guestName`, `guestEmail`, `guestPhone`, `guestAddress` fields.
- **`RequestDocument.requestId` is nullable (`String?`)**, allowing orphan documents not linked to any request.
